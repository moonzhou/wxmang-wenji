## 一、收文口径（三条，不可放宽）

| # | 规则 | 理由 |
| - | --- | --- |
| 1 | **只收真实署名 `wxmang` 的条目** | 源站是论坛聚合站，收录 380 余位作者。原梳理按**标题关键词**推测作者，实测严重失真 |

## 三、正文提取规则

源页面结构：

```html
<div class="POST">
  <p>正文…</p>
  <p>关键词(Tags): … 管理推：… 通宝推：… , 65 条留言</p>   ← 论坛元数据，必须剔除
  <div class="LI">   ← 留言区起点，其后内容全部剔除
    <div class="USER">…</div><div class="SAY">…</div><div class="REPLY">…</div>
  </div>
</div>
```

三条必须遵守：

1. **正文 = `<div class="POST">` 内、首个 `<div class="LI">` 之前的内容。**
   留言区不是 wxmang 的作品，收录会造成署名责任不清；其中还含网友个人信息。
2. **尾部论坛元数据行必须剔除。** 形如 `关键词(Tags): …`、`管理推：…`、
   `通宝推：…`、`N 条留言`。**不剔除会导致去重失效**——同一篇的搬家版本
   因留言数不同而被判为不同文章。
3. **正文首行统一注入溯源行**，格式固定：

   ```markdown
   > 作者：wxmang ｜ 首发：2011-01-30 ｜ [原文链接](https://wxmang.site/html/1_3265961.html)
   ```

   写成正文而不是模板，是为了让溯源跟着内容走：换主题、把文集单独抽成站点、
   导出 PDF，溯源都不会丢。合并了多条的篇目，溯源行列出全部原始链接。

### 段落是重建的（必须知道）

源站 `<p>` 是原论坛按约 40 字折行的产物，**真正的段落结构在源头就已丢失**。
`fetch_articles.py` 用「编号行（`1、`/`一、`/`（一）`）独立成段 + 上一行以句末标点
结尾则另起段 + 其余直接拼接」的规则重建段落。

比逐行成段可读得多，但它**是重建的，不是原文分段**。若发现某篇分段明显有误，
记下来，将来可考虑按标题结构手工校正重点篇目。

## 四、去重规则

判据写在 `_tools/wxlib.py`，两条并用：

1. **整体相似度**：`difflib.SequenceMatcher.ratio() ≥ 0.97` → 同一篇的搬家版本。
   典型差异只有一两行，例如「1、原材料」在某版被改成「一、原材料」。
2. **包含关系**：短的那份有 `≥ 0.95` 的比例被长的那份覆盖 → 同一篇的不同版本。
   实测案例：「八宝饭」早期版比搬家版多出 3 条「技术控制要点」，
   相似度只有 0.907 抓不到，但短的那份几乎整篇都在长的里面。
   这与规则 1 的差别在于：**允许一版是另一版的截断/扩写**。

比对范围：按正文长度排序后，只在长度相近（差 ≤ 30%）的区间内两两比对。

> ⚠️ **踩过的坑（务必保留这个教训）**：最早用「正文前 60 字」分桶，
> 结果「回锅肉」的两个版本因第 41 字处的一处差异（`1、` vs `一、`）
> 被分进不同桶，**永远没有被比对**——而它们真实相似度是 0.9994。
> 任何基于前缀的哈希分桶都可能这样静默漏判。**不要改回分桶。**

保留策略：

- **日期**取组内最早的一条（最早出现的归属时间）
- **正文**取组内**最长**的一条（搬家版常丢尾部段落，用最早版会截短内容）
- `SOURCES.csv` 中保留全部原始链接；`body_from` 记录正文取自哪个链接

## 五、字段规范

front matter **禁止出现** `tags` / `categories` / `series` / `author` 四个键——
它们在站点全局注册为分类法，一旦出现，488 篇会把 `/tags/` 与 `/series/` 冲垮。
文集改用自定义参数：

| 字段 | 含义 |
| --- | --- |
| `wx_author` | 固定 `wxmang` |
| `wx_cat` | 主题大类（由所在目录通过 cascade 注入） |
| `wx_series` | 系列名（由所在目录通过 cascade 注入） |
| `source_url` / `source_urls` | 原始链接 |
| `original_date` | 首发日期 |
| `excludeFromSearch` | 固定 `true`（隔离：488 篇全文不进全站搜索索引） |
| `weight` | 系列内阅读顺序 |

## 六、目录与 URL

- 仓库里**目录名用中文**（可读性优先），URL 由 `_tools/taxonomy.py` 映射为 ASCII。
- 未登记映射的系列，URL 回落为中文目录名。
- 系列达到 `SERIES_MIN = 3` 篇才单独建目录，其余留在所属大类根目录。
- 系列归属由 `taxonomy.SERIES_CAT` **人工登记**。不要改成按文章自带的「主题分类」投票——
  那个字段和作者归属一样是标题关键词猜的，实测会把「标准化菜谱」投进管理学。

## 七、站点侧的三条约束（易踩）

1. **Hugo 只忽略以 `_` 或 `.` 开头的「文件」，不忽略「目录」。**
   仅靠 `_meta/` 这样的目录名是拦不住的——`_meta/*.md` 会被渲染成页面，
   `_tools/*.py` 会被当作静态文件复制进 `public/`。
   必须在 `zmsite/config/_default/hugo.toml` 的 `ignoreFiles` 里显式列出。
2. **`cascade` 会作用到声明它自己的那个页面上。** 所以在文集根 `_index.md` 写
   `excludeFromSearch: true` 会把入口页本身也排除掉，读者搜不到这一栏。
   隔离参数下沉到大类 `_index.md` 声明。
3. **`README.md` / `LICENSE` 也会被 Hugo 当内容处理。** 同样靠 `ignoreFiles` 排除。
