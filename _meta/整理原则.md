# 整理原则

> 面向维护者。站点读者请看 [`about/index.md`](../about/index.md) 或
> <https://zmsite.top/wxmang/about/>。

## 一、收文口径（三条，不可放宽）

| # | 规则 | 理由 |
| - | --- | --- |
| 1 | **只收真实署名 `wxmang` 的条目** | 源站是论坛聚合站，收录 380 余位作者。原梳理报告按**标题关键词**推测作者，实测严重失真 |
| 2 | **署名以页面 `<p class="author">` 为准** | 这是页面自带的元数据。任何按标题、按批次、按编号的推测都不作为依据 |
| 3 | **重复发布合并为一篇** | 同一篇文章在多个论坛批次重复出现。合并后保留最早日期，全部原始链接汇入 `SOURCES.csv` |

## 二、口径修正记录（2026-09-25）

原梳理报告（`wxmang-梳理/wxmang-文集梳理报告.md`）给出的口径是
「站点 1421 条 / wxmang 本人 1272 篇（89.5%）」。全量抓取真实署名后修正如下：

| 口径 | 篇数 | 说明 |
| --- | --- | --- |
| 源站条目总数 | 1421 | 首页单页索引，无分页 |
| 原报告推测为 wxmang | 1272 | ❌ 按标题关键词推测 |
| **实际真实署名 wxmang** | **773** | ✅ 页面 `author` 字段 |
| **去重后唯一篇目** | **562** | ✅ 合并 211 条重复发布 |

推理错误的分布（全量交叉验证，非抽样）：

| 情形 | 条数 |
| --- | --- |
| 推测为 wxmang、实际也是 wxmang | 751 |
| **推测为 wxmang、实际是他人** | **521**（误报） |
| 推测为他人、实际是 wxmang | 22（漏报） |
| 推测为他人、实际也是他人 | 127 |

**结论：标题关键词不能作为署名依据。** 原报告第 1 篇「那些杀手都很冷」
标为 wxmang，实测页面署名为「夏翁」；报告所称的「2005 年首篇」也不成立，
实际文集的起点是 2009 年。

## 三、正文提取规则

源页面结构：

```html
<div class="POST">
  <p>正文…</p>
  <p>关键词(Tags): … 管理推：… 通宝推：… , 65 条留言</p>   ← 论坛元数据，必须剔除
  <div class="LI">   ← 留言区起点，其后内容全部剔除
    <div class="USER">…</div><div class="SAY">…</div><div class="REPLY">…</div>
  </div>
</div>
```

三条必须遵守：

1. **正文 = `<div class="POST">` 内、首个 `<div class="LI">` 之前的内容。**
   留言区不是 wxmang 的作品，收录会造成署名责任不清。
2. **尾部论坛元数据行必须剔除。** 形如 `关键词(Tags): …`、`管理推：…`、
   `通宝推：…`、`N 条留言`。**不剔除会导致去重失效**——同一篇的搬家版本
   因留言数不同而被判为不同文章（实测：不剔除时 1421 条只认出 5 组重复；
   剔除后 773 条认出 211 条重复）。
3. **正文首行统一注入溯源行**，格式固定：

   ```markdown
   > 作者：wxmang ｜ 首发：2011-01-30 ｜ [原文链接](https://wxmang.site/html/1_3265961.html)
   ```

   写成正文而不是模板，是为了让溯源跟着内容走：将来换主题、把文集单独抽成站点、
   甚至导出 PDF，溯源都不会丢。合并了多条的篇目，溯源行列出全部原始链接。

## 四、去重规则

两级，判据写在 `_tools/wxlib.py`：

1. **精确**：正文去空白后指纹完全相同 → 合并。
2. **近似**：长度相差 ≤6% 且 `difflib.SequenceMatcher.ratio() ≥ 0.97` → 合并。
   同一篇的搬家版本常有细微差异，例如「1、原材料」在某版被改成「一、原材料」，
   差异只有一行，精确比对抓不到。

保留策略：**保留最早日期的那条**作为代表，其余版本只贡献原始链接。

> ⚠️ 近似去重是启发式的，阈值调整需先用样本验证。当前阈值下仍可能漏合并
> （例如「标准化菜谱」27 条只合并到 12 篇，实际同一道菜有 3 个版本，
> 说明部分版本的正文差异超过 3%）。**首次全量入库前需人工抽查一遍合并组。**

## 五、字段规范

front matter **禁止出现** `tags` / `categories` / `series` / `author` 四个键——
它们在站点全局注册为分类法，一旦出现，562 篇会把 `/tags/` 与 `/series/` 冲垮。
文集改用自定义参数：

| 字段 | 含义 |
| --- | --- |
| `wx_author` | 固定 `wxmang` |
| `wx_cat` | 主题大类（由所在目录通过 cascade 注入） |
| `wx_series` | 系列名（由所在目录通过 cascade 注入） |
| `source_url` / `source_urls` | 原始链接 |
| `original_date` | 首发日期 |
| `excludeFromSearch` | 固定 `true`（由文集根 cascade 注入） |
| `weight` | 系列内阅读顺序 |

## 六、目录与 URL

- 仓库里**目录名用中文**（可读性优先），URL 由 `_tools/taxonomy.py` 映射为 ASCII。
- 未登记映射的系列，URL 回落为中文目录名。
- 系列达到 `SERIES_MIN = 3` 篇才单独建目录，其余留在所属大类根目录。
